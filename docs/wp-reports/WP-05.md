# WP-05 — SettingsStore

Date: 2026-11-08

## Delivered

Implemented typed DataStore settings with defaults/model validation/clamping, API-key-set flow, synchronous typed reads per the public contract, AES-256-GCM encryption with fresh IVs, Android Keystore key generation, and StrongBox fallback. Blank API-key input clears the key.

## Verification

Two Robolectric tests pass: defaults and every clamp boundary; API key encrypt/decrypt, ciphertext changes with a fresh IV, no plaintext in the actual DataStore file, reopening a fresh DataStore instance against the same file, and clearing the gate.

The combined offline `:app:testDebugUnitTest` and `:app:assembleDebug` run passed (45 tests passed, 3 opt-in live tests skipped); `:app:lintDebug` passed. See WP-07 for the separately run live API outcomes.

## Assumptions and conflicts

[ASSUMPTION] The test-only internal constructor injects a real AES key and real DataStore, since Robolectric is not a hardware Keystore/StrongBox implementation. Production construction always obtains its key from AndroidKeyStore. Hardware-backed persistence and StrongBox fallback still need device validation; they are not claimed as tested. Synchronous reads should be called from worker/IO contexts; the gateway executes on Dispatchers.IO.
