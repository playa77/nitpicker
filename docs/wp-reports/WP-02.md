## Assumptions and conflicts

[CONFLICT] Room annotations cannot express CHECK constraints. The AppDatabase factory callback rebuilds the newly created empty tables with the approved CHECKs, preserving generated columns and indices. The generated Room JSON remains an honest KSP export; `schema-v1.sql` records the CHECK-bearing SQL. Callers must use `AppDatabase.builder` / `inMemoryBuilder`, not a bare Room builder. Additional child-FK indices follow Room recommendations.

[ASSUMPTION] The spec has no durable segmentation-in-flight field/state. Claims are exclusive within the singleton DAO, guarded by the database view/CAS and a process-local set; recovery clears that set. Completion is durable through the CHUNK job. Multiple concurrently active AppDatabase instances for the same file are outside this single-process singleton contract.
